### How should Doomscroll Count work?

Create configurable rules:

- Session longer than 5 minutes = one prolonged-scroll event.
- Session longer than 15 minutes = one excessive-scroll event.
- Reopen the same app within 60 seconds = rapid-reopen event.
- Use a selected app during bedtime = nighttime-scroll event.
- Exceed the daily budget = daily-overuse event.

Do not count every long session as a separate doomscroll if it is already part of an ongoing session. Use event deduplication and configurable cooldowns.

Technical distinction: Android can reliably provide foreground app duration and app transitions with Usage Access. Exact Reels, Shorts and individual feed swipe counts are not reliably available through ordinary usage statistics. They require additional UI detection, which can be fragile, app-version-dependent and subject to accessibility policies. Present estimated feed activity separately from verified app usage.

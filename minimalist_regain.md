# 4. What can actually be replicated using Expo?

This is where we need to be careful. You can reproduce the product experiences, but not all Android and iOS functionality is equally accessible.

| Feature                | Expo UI | Native Android                         | iOS                    |
| ---------------------- | ------- | -------------------------------------- | ---------------------- |
| Screen-time reports    | Yes     | UsageStatsManager                      | DeviceActivity         |
| App timers             | Yes     | Usage monitoring                       | DeviceActivity         |
| App blocking           | Yes     | Accessibility / supported restrictions | ManagedSettings        |
| Strict mode            | Yes     | Multiple native mechanisms             | Screen Time APIs       |
| Reels blocking         | Yes     | Accessibility-based detection          | Very limited           |
| YouTube Study Mode     | Yes     | App-specific detection                 | Very limited           |
| Minimal launcher       | Yes     | Default launcher role                  | Not supported          |
| Mindful opening        | Yes     | App transition detection               | Limited                |
| Notification filtering | Yes     | NotificationListenerService            | Not equivalent         |
| Website blocking       | Yes     | VPN/DNS or browser filtering           | Managed restrictions   |
| Grayscale              | Yes     | Native settings mechanisms             | Limited                |
| Focus rooms            | Yes     | Shared backend                         | Shared backend         |
| Music and themes       | Yes     | Native audio as needed                 | Native audio as needed |
| Smart alarms           | Yes     | AlarmManager                           | Local notifications    |
| Parental controls      | Yes     | Native/managed-device APIs             | FamilyControls         |

Apple's Screen Time architecture is fundamentally different from Android's app-monitoring model. Regain itself uses FamilyControls, DeviceActivity and ManagedSettings on iOS, with opaque application-selection tokens.&#x20;

# 7. Important product and IP considerations

You can implement equivalent functionality and study publicly documented product behaviour. However:

- Don't copy their proprietary source code.
- Don't reproduce their exact branding, illustrations, text or distinctive UI assets.
- Create original NeuronNinja designs and interactions.
- Avoid claiming a feature is supported on every device when it depends on Android manufacturer restrictions.
- Validate Google Play's Accessibility API, installed-app visibility, exact-alarm and VPN policies before release.
